# 音频与特效现状及规划

本页覆盖音频、粒子、后处理、视频与媒体。这些能力目前都没有可用的运行时实现，但资产与渲染侧已经有确定的接入点。

## 当前状态：规划中

### 已有

- 工件清单已经定义 `Audio` 类型，可以登记音频工件；
- 资产依赖记录支持源文件哈希、导入器版本与构建目标，音频导入可以复用同一套依赖跟踪；
- UI 侧有 `UILocalizationTable`，为后续多语言音频与文本准备了一致的本地化模型；
- 编辑器已经具备面板、菜单与命令注册机制，可以承载后续音频与特效编辑器。

### 缺失

- 没有音频设备、混音器、资源播放或空间音频；
- 没有粒子系统与粒子渲染路径；
- 没有后处理栈（bloom、色调映射、颜色分级等）；
- 没有视频播放、时间线与过场动画系统。

注意区分：延迟渲染路径已经包含 Decal 与透明物体的处理，但它们属于场景着色，不是“视觉特效系统”。

## 目标

| 领域 | 目标描述 |
| --- | --- |
| 音频资源 | 支持常见压缩格式，导入为运行时工件 |
| 音频播放 | 一次性播放、循环播放、音量与音高 |
| 空间音频 | 三维衰减、方向性与听者位置 |
| 混音 | 总线、效果器与快照 |
| 粒子 | 发射器、模块化更新、GPU 驱动的绘制 |
| 后处理 | 至少包含色调映射、颜色分级、泛光与景深 |
| 视频 | 播放容器与音频轨同步 |
| 时间线 | 在编辑器内编排镜头、音频与事件 |

## 依赖与顺序

1. 音频需要一个**平台音频后端**抽象，与 RHI 的做法一致：上层只依赖抽象，后端负责设备与格式差异。选择后端属于架构决策。
2. 音频播放需要每帧的听者与声源变换，可以在现有组件更新循环内完成。
3. 粒子需要一条批量实例化绘制路径，与已有的实例化与绘制命令缓存协作，见[渲染概览](../rendering/overview.md)。
4. 后处理是渲染 pass，应当作为 FrameGraph 节点加入前向与延迟两条路径，而不是独立的渲染循环。
5. 视频解码需要平台或第三方解码器，且必须解决与渲染线程的资源交接问题。
6. 时间线编辑器需要场景序列化之上的新资产类型，遵循[反射与序列化](../architecture/reflection-serialization.md)。

## 不作为承诺
