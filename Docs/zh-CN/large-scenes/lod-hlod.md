# LOD 与 HLOD

LOD 用不同细节层级表现同一个网格；HLOD 用代理对象表现一组对象。两者都是“用更少的绘制换更远的视角”，区别在粒度。

## 静态网格 LOD

静态网格的 LOD 在导入阶段构建，运行时只做级别选择：

| 阶段 | 工作 |
| --- | --- |
| 导入 | 按导入设置生成各级网格数据并打包工件 |
| 运行 | 根据视图距离与屏幕尺寸选择级别 |

导入设置里的关键字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `lodGroup` | `None` | LOD 组预设 |
| `minLOD` | `0` | 允许使用的最低级别 |
| `autoComputeLODScreenSize` | `true` | 是否自动计算各级屏幕尺寸阈值 |
| `sourceModels` | 每个 LOD 一项 | 各级的来源类型、屏幕尺寸与网格数据 |

来源类型区分 `Imported`、`Authored` 与 `Generated`。由简化流程生成级别时，三角形比例与像素误差来自 LOD 组预设。

LOD 组预设把多个网格的切换阈值统一起来：同一组的网格在同一距离切换，避免相邻物体细节跳变不一致。

## HLOD

HLOD 把一组对象在远处替换为代理对象。实现要求：

- 决策保持视图局部，不写入共享状态；
- 编辑器选中的 HLOD 子对象必须仍可检查，不能因为被代理而丢失可操作性；
- 透明、顺序相关、蒙皮与动画子对象在具备显式代理兼容性之前不参与抑制。

这两条决定了 HLOD 的可用范围：静态且不透明的子集可以较早进入，其余需要额外的兼容性工作。

## 与可见性的关系

可见性管线先收敛候选集，LOD/HLOD 再决定每个候选用什么表示。顺序不能颠倒：先做 LOD 再剔除会把工作花在最终不可见的对象上。

## 与资源驻留的关系

HLOD 代理与低级别网格是独立工件，它们参与资源驻留统计与预算。把 HLOD 引入场景之前先确认预算模型能覆盖代理网格，否则远端视角会引入新的加载尖峰，见[资源驻留与预算](streaming.md)。

## 验证关注点

- 串行、并行与全量扫描模式下 LOD 选择结果一致；
- 快速移动相机时不出现级别抖动；
- HLOD 抑制不会隐藏编辑器需要操作的子对象；
- 被代理对象的资源在驻留系统中按低级别统计。
