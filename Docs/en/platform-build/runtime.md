# Game Runtime and Asset Manifests

The editor produces artifacts and the `Game` runtime consumes them. This page covers how the runtime starts, how it loads assets, and the command-line entry point.

## Runtime entry points

| Executable | Purpose |
| --- | --- |
| `Launcher` | Project list, project creation, and opening projects |
| `Editor` | The editor and its Play mode |
| `Game` | Standalone execution of project content |

All three share the same runtime modules: the scene system, asset database, render pipeline, and script backends are one implementation. `Game` is not a stripped copy of the editor.

## Game command line

```text
Game [options] [project_path]
```

| Option | Notes |
| --- | --- |
| `--backend <name>` / `-b <name>` | Select the graphics backend |
| `--renderdoc` / `--no-renderdoc` | Toggle RenderDoc integration |
| `--capture-after-frames <N>` | Auto-capture after N presents, enabling RenderDoc |
| `--material-validation-output <path>` | Write a renderer readback PNG for material validation |
| `--material-validation-summary <path>` | Write material validation analysis text |
| `--material-validation-after-frames <N>` | Run material validation after N presents |
| `--material-validation-swapchain` | Capture the presented Game output |
| `--help` / `-h` | Help |

`project_path` may be a `.nullus` project file or a project directory.

```powershell
Game.exe TestProject.nullus
Game.exe --backend dx12 TestProject
```

## Asset manifests

At startup the runtime resolves the runtime asset database from project settings:

1. Locate the project settings file.
2. Resolve the runtime artifact database path from project settings.
3. Load the runtime asset database.
4. Prewarm root assets such as materials as needed.

```text
project settings -> runtime artifact database -> asset reference resolution -> resource prewarm
```

Artifact manifests record a target platform and loader per artifact, and the runtime only accepts artifacts matching the current platform. `ArtifactType` covers model, mesh, material, texture, skeleton, skin, animation clip, morph target, Prefab, scene, shader, audio, UI document, style sheet, font, and localization table.

Prefab roots generated by model import reference their embedded meshes and materials as sub-assets, using each sub-asset's own source identity. That lets runtime prewarm reach those materials without changing asset or serialization formats.

## Runtime artifact authorization

The runtime only reads artifact paths registered as authorized. Unauthorized paths are rejected and logged, so a game process cannot reach arbitrary files inside the project. Authorization is established from manifests during startup.

## Project file and session

The Game runtime reads the project file's startup options:

- `x_resolution` / `y_resolution` / `fullscreen`: window and presentation
- `vsync`: vertical synchronization, shared with the editor
- `graphics_backend`: preferred backend
- `start_scene`: startup scene, falling back to `last_opened_scene` when empty
- `dev_build`: development build marker
- `enable_threaded_rendering`: threaded rendering toggle
- `renderdoc_startup_capture_frames`: automatic startup capture

The full key list is in [Editor and Project Settings](../editor/settings.md#project-file).

## Packaging and distribution

`NullusBuild` and editor build actions share dependency collection, cooking, content packaging, and Player assembly. Project `BuildProfiles.json` selects the target, start scene, keep rules, and output format. See [Player Packaging and Distribution](packaging.md) for configuration and commands.

A packaged executable reads adjacent `Player.info`, which records engine version, target, packages, script payload, and input hash. It checks compatibility before mounting `.npak` content and loading the runtime asset manifest. The package does not depend on the editor's `Library/`; development-project startup can still use the artifact database.

`--package-self-test` runs before normal launch argument parsing and checks containers, the manifest, start scene, and script payload. Passing these checks does not establish game interaction or GPU rendering acceptance. Installers, automatic updates, and mobile distribution remain unavailable.
