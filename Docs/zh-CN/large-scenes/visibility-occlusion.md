# 可见性与遮挡剔除

大场景的性能问题通常不是“画得太慢”，而是“算得太多”。可见性管线的职责是在进入绘制之前把候选集收敛到真正需要提交的对象。

## 可见性管线

一次可见性求解包含：

1. 从空间索引取出视锥范围内的候选对象；
2. 按表示与可见性规则过滤；
3. 输出稀疏的图元句柄集合；
4. 把结果交给绘制命令构建阶段。

管线支持多种执行模式用于对照验证。串行、并行与全量扫描三条路径必须产出一致的可见集与稀疏句柄输出；并行路径使用不可变快照，并在调度不可用时安全回退。

保留的场景状态必须保持代次安全：图元句柄限定在场景范围内、带代次检查、移除后打墓碑标记，快照不持有活的组件指针。

## 空间索引

索引重建不允许出现隐藏的整表扫描或多帧同步重建。允许的做法是：

- 显式遥测与计数器，让每次重建的规模可见；
- 保留上一份可用数据，重建期间继续服务查询；
- 脏区标记与分阶段重建；
- 明确的每次预算上限。

静默的重建峰值视为缺陷。

## HZB 遮挡剔除

HZB（层级深度缓冲）遮挡剔除在 DX12 上按设备能力保守启用：

- 能力来自 `RHIDevice::GetCapabilities()` 与纹理格式能力，不来自后端名字；
- 不支持的能力组合下，图元保持可见，并记录回退原因；
- 普通遮挡帧不引入同步回读、阻塞映射或 CPU/GPU 围栏等待。

### 保守规则

以下情况一律保持可见，不进行遮挡剔除：

- 历史数据无效或过期；
- 对象在本帧移动；
- 对象渲染表示发生变化；
- 深度信息不合格；
- 设备能力不满足。

### 验证方式

HZB 的证据是按后端记录的。DX12 的一次抓帧不能证明 Vulkan、Metal、DX11 或 OpenGL 的行为。

A/B 验证要求：

- 同一项目、场景、相机、构建、遮挡栈大小与抓帧帧号；
- 在项目的 `UserSettings/editor-settings.json` 中设置 `objects["editor.large-scene"].fields.enableHZBOcclusion`；
- 启用侧应能看到 `HZBBuild` 与 `HZBOcclusion` 派发位于延迟光照之前；
- 关闭侧应看到延迟光照与编辑器网格绘制，且计算派发为零；
- 运行时日志确认关闭标志确实跳过了渲染器的 HZB 数据与资源准备。

改动 HZB 着色器、绑定、资源转换、派发尺寸、回读或 pass 顺序时，需要重新采集证据。

## 调试叠加层

编辑器提供可见性调试叠加层，显示剔除原因等统计。

约束：调试叠加层与 Frame Info 只消费渲染器发布的快照。叠加层被关闭时，不得遍历活动场景、同步渲染场景或排空资源队列。

## 相关设置

| 位置 | 项 | 说明 |
| --- | --- | --- |
| `UserSettings/editor-settings.json` | `editor.large-scene.enableHZBOcclusion` | HZB 遮挡开关 |
| 编辑器菜单 | `Debugging > Debug Draw` | 叠加显示调试信息 |
| 项目设置 | 可见性策略选项 | 默认保持保守 |
