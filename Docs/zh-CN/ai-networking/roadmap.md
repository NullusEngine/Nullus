# AI 与联网现状及规划

本页覆盖游戏 AI（导航、决策）与多人联网。前者已经有一小块可用的原生基础，后者尚未开始。

## AI：部分实现

### 已有

`Runtime/Engine/AI` 提供两个原生状态机：

| 类型 | 说明 |
| --- | --- |
| `StateMachine` | 状态与转移的集合，`Update(dt)` 推进当前状态 |
| `PushdownMachine` | 带状态栈的下推自动机，适合可中断与可恢复的流程 |
| `State` | 持有更新函数的状态节点 |
| `StateTransition` | 状态之间的转移 |

这些是原生 C++ 类型，用于引擎内部与原生逻辑。它们没有进入脚本 API 清单，因此 C# 与 Lua 目前不能直接构造状态机。

### 缺失

- 导航网格生成、路径查询与动态避障；
- 行为树；
- 感知系统（视野、听觉）；
- 群体行为；
- AI 调试可视化与运行时查看器。

## 联网：未实现

没有任何网络传输、会话管理、复制或同步代码。当前也没有为网络预留的组件。

## 目标

| 领域 | 目标描述 |
| --- | --- |
| 导航 | 导航网格生成、路径查询、动态障碍与避障 |
| 决策 | 行为树与感知系统，能在编辑器中编辑与调试 |
| 群体 | 局部避让与群体编队 |
| 传输 | 底层传输抽象，支持可靠与不可靠消息 |
| 会话 | 会话建立、加入、断开与重连 |
| 复制 | 对象与属性复制、权限归属与滚动校正 |
| 确定性与回放 | 记录与回放输入，用于调试与验证 |

## 依赖与顺序

1. `StateMachine` 与 `PushdownMachine` 要提供给脚本使用，先要进入 API 清单并补齐可移植签名，见[脚本 API 参考](../scripting/api.md)。
2. 导航依赖空间索引与几何查询。几何查询与物理的查询设施重叠，应共用基础设施，见[物理现状与规划](../physics/roadmap.md)。
3. 行为树需要编辑器支持与新的资产类型，遵循[编辑器脚本扩展](../architecture/editor-extensions.md)与[反射与序列化](../architecture/reflection-serialization.md)。
4. 联网的复制层需要与场景对象生命周期协作：对象创建、销毁与激活状态都需要稳定的网络标识。这要求先定义对象标识在网络中的表示方式。
5. 联网与多线程渲染的交互需要明确：网络回调运行在哪个线程、如何产生场景命令。按现有模型，网络回调应产生命令而不是直接改渲染状态，见[任务系统与线程模型](../architecture/jobs-threading.md)。
