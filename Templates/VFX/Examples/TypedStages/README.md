# Bool and Int32 particle values

Copy the whole directory into a project's Assets directory and open
`TypedSystem.vfx` in **Window > Particle Editor**. Open the module/emitter
sources in **Window > Particle Library Editor**.

The System runs one CPU emitter and one inherited GPU emitter. Their shared
Integer State module initializes `Particles.Counter` from the Int32 parameter
`User.Counter`, whose default is **16777217**. Each update adds `User.Step` with
integer arithmetic. That default exceeds the exact integer range of Float and
is preserved through saving, compilation and CPU/GPU storage.

`User.UseLarge` is Bool. It selects the counter value and particle color and
writes `Particles.Flag`. The module's static Bool input selects initialization
or accumulation at compile time. Its graph demonstrates Int32 addition, Bool
selection and a static switch. Floating point and integer arithmetic require
an explicit Convert node when crossing types.

The GPU stage uses **Bool** `User.StageEnabled` and **Int32**
`User.StageIterations`. Change their preview overrides in **User Parameters**;
these updates freeze in a world frame and do not recompile the System.
**Parameters** edits saved defaults. Int32 controls use integer text input and
Bool controls use checkboxes. The graph editors support typed constants,
comparison, logical operations, selection and scalar conversion.

Int32 uses all 32 bits, including signed minimum/maximum. Arithmetic wraps in
two's-complement form; division by zero yields zero, and minimum divided by -1
remains minimum. Bool uses Niagara's canonical -1/0 mask. JSON stores native
integers and true/false, and the CPU/GPU buffers preserve those bit patterns.

The component exposes `SetIntParameter(name, value)` and
`SetBoolParameter(name, value)` through the generated Script API, alongside the
existing float/vector methods. Typed setters reject incompatible declared
types. C#/Lua declarations are generated by the normal Engine build.

```text
NullusVfxCompile compile Templates/VFX/Examples/TypedStages/TypedSystem.vfx build/TypedSystem.compiled.json --backend all
```

Typed System/script/emitter sources and cooked programs use format **4**;
runtime settings use format **2** and Shader layout **11**. Existing float
sources and compatible layout-10 packages remain readable. Cooked programs
retain typed defaults, stage controls and instructions after graphs/HLSL and
library sources are stripped. This example does not establish complete UE
module/renderer/type parity or Linux/Metal device acceptance.
