# 动画现状与规划

本页说明动画与角色能力当前到哪一步、哪些是已有基础、缺口在哪里，以及实现顺序受什么约束。内容按“状态—证据—依赖”组织，不承诺版本与时间。

## 当前状态：部分实现

### 已有

- 导入器会保留骨骼、蒙皮、动画片段与形变目标数据，并在工件清单中以 `Skeleton`、`Skin`、`AnimationClip`、`MorphTarget` 类型登记；
- 这些工件参与依赖跟踪与版本管理，源文件或导入器变化时按规则重新生成；
- 组件更新循环已经区分普通更新、固定更新与后置更新三个阶段（`OnUpdate`、`OnFixedUpdate`、`OnLateUpdate`）。

### 缺失

- 没有运行时蒙皮组件：导入的骨骼与蒙皮数据目前无法在运行时驱动网格；
- 没有动画片段播放器、状态机、混合或过渡；
- 没有动画编辑器与动画曲线资产；
- 没有角色控制器。

`ModelPrefabBuilder` 在遇到带蒙皮或动画的模型时会显式记录诊断码 `runtime-skinning-component-missing`，提示“导入的骨骼、蒙皮与动画数据已保留为工件，但在运行时蒙皮组件出现之前，静态生成的 Prefab 无法播放它们”。这条诊断是当前状态的权威说明。

UI 侧有一个独立的 `UIAnimationPlayer`，只提供不透明度轨道，服务于界面动画，不是角色动画系统。

## 目标

| 能力 | 目标描述 |
| --- | --- |
| 运行时蒙皮 | 用骨骼层级驱动网格顶点，支持单骨骼根与多根 |
| 动画片段 | 采样关键帧、循环模式、播放速率 |
| 动画状态机 | 状态、过渡条件、混合时长 |
| 混合 | 单层混合与遮罩混合 |
| 形变目标 | 权重驱动的形变 |
| 动画编辑器 | 在编辑器内查看与调整片段、状态机 |
| 角色控制 | 与物理或独立的运动学控制器配合 |

## 依赖与顺序

1. **运行时蒙皮组件**是其余能力的前置条件。片段播放、状态机与角色控制都需要一个能消费骨骼数据的目标。
2. 蒙皮需要网格工件携带骨骼权重与骨骼索引，并需要一个按骨骼变换更新顶点的渲染路径。这依赖渲染侧的实例数据与常量更新，属于[渲染架构](../rendering/overview.md)的范围。
3. 动画片段与状态机需要新的资产类型与序列化支持，遵循[反射与序列化](../architecture/reflection-serialization.md)的字段与引用规则。
4. 角色控制需要运动学或动力学求解。运动学版本可以在没有物理系统的情况下先行；动力学版本依赖[物理与交互](../physics/roadmap.md)。
5. 编辑器侧需要在现有 Inspector 与面板模型中新增编辑器，遵循[编辑器脚本扩展](../architecture/editor-extensions.md)的注册约定。

## 不作为承诺

本页描述的是目标与依赖，不是排期。实现状态变化时以[功能状态矩阵](../roadmap/index.md)与源码为准。
