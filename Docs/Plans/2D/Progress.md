## Phase 1 implementation

- SpriteArtifact v1 adds validated binary descriptors, persistent child UUIDs, pivot/PPU geometry and sibling texture dependencies. Texture keeps its primary identity. Editor and Cook share the descriptor builder. Runtime loading supports packaged artifacts and retains the last valid revision after invalid reloads.
- SpriteRendererComponent uses reflection, serialization, PPtr and scene fast-access mechanisms. The scene proxy registry captures immutable geometry, material/shader/texture owners, transforms, sorting and tint; components do not escape to the render thread.
- SpriteSceneRenderer culls and sorts before adjacent batching. Instanced and CPU-expanded paths record real RHI buffers, binding sets and draws. Mesh/VFX carry shared transparent sort keys; merging retains resource edges and splits Sprite batches around intervening foreign draws.
- SpriteUnlit ShaderLab/material, alpha picking, source/child presentation, Single Sprite texture drop normalization, subtree creation/Undo, import controls and sorting-layer editing are connected. Full visible Editor acceptance is pending.
- Sorting layers have persistent IDs, a versioned project table, transactional Undo and base-package inclusion. Immutable per-view statistics and the CPU batching switch appear in existing Scene View advanced controls.
- The 2D template contains an orthographic camera, Sprite, deterministic texture and stable references. Launcher deploys it. Editor and Game apply project timing: new 2D templates use 1/60 second and eight maximum fixed steps; projects without these keys retain existing timing.
- Shared Camera GPU projection maps depth to [0,1]; CPU projection remains compatible with existing rays/frusta. Frame bindings, light grid, VFX, Sprite, HZB/distance-field inputs and editor grid use GPU projection. The temporary Sprite-only shader conversion was removed.
